# Horus Find Similar, Settings and the First-Run Model Step (Plan 5 of 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search option B, "Find similar". It is an optional, offline image–text model (Google SigLIP base) that the artist downloads once. It finds references that *look* alike, from a library image, a dropped image or typed words. Its results are labelled "Looks similar" and always kept apart from the technique-based "Related" list.

**Architecture:**
- **A new Rust module family, `app/src-tauri/src/similar/`:**
  - `model`: the pinned model artifact table;
  - `download`: a resumable download with a SHA-256 check;
  - `encoder`: ONNX Runtime sessions, SigLIP preprocessing and the tokenizer;
  - `store`: `embeddings.bin` in the library folder, plus brute-force cosine top-k;
  - `indexer`: a low-priority background worker that embeds references in pausable batches.
- **Thin Tauri commands** expose status, enable, disable, remove and pause, plus the three searches. Progress reaches the UI as Tauri events.
- **TypeScript UI:**
  - a Settings panel with the Find similar section;
  - the first-run step from Plan 1 Task 9, now able to start the real download;
  - a "Looks similar" tab in the Reference view's margin;
  - a "Looks similar" section in the search dropdown;
  - an image drop target.

  None of them exists in the DOM while the feature is off.

**Tech Stack:**
- Plan 1's stack: Tauri 2, Rust (edition 2024), TypeScript and Vite, and Vitest with jsdom.
- New crates:
  - `ort = "=2.0.0-rc.15"`: the newest release on crates.io as of 25 Nov 2026. There is no stable 2.x, so pin it exactly.
  - `tokenizers = { version = "0.23", default-features = false, features = ["fancy-regex"] }`: pure Rust, no Oniguruma C build.
  - `sha2 = "0.11"`.

| Model | Google SigLIP base, patch 16, 224 px (`google/siglip-base-patch16-224`, Apache-2.0). The ONNX export used is `Xenova/siglip-base-patch16-224` on Hugging Face |
| Pinned revision | `4649052661e53c7000355844105f8a1792088239` |
| Vision encoder | `onnx/vision_model_quantized.onnx`: 99,499,129 bytes, SHA-256 `ef14a954f3d57e1806666432bd9785004c1dc27100aa260eee0cb0f10a5de058` |
| Text encoder | `onnx/text_model_quantized.onnx`: 111,475,220 bytes, SHA-256 `ad0329b1f35acc66d8953ff2559ce358da8eb0a7011794cf951523d63a4dbce2` |
| Tokenizer | `tokenizer.json`: 2,398,744 bytes, SHA-256 `4a17c975210be5ab4c36b47d8dae4eefb866dbfb1e676e394aad85dc30a3ae08`. It is a SentencePiece Unigram tokenizer with a Metaspace pre-tokenizer, and `tokenizers` 0.23 reads it. Its normalizer has **no** lowercasing, but `tokenizer_config.json` sets `do_lower_case: true`, `model_max_length: 64` and `pad_token: "</s>"`. So the app lowercases the text itself, then pads or truncates to **64** tokens with `</s>` (id 1). The text model takes `input_ids` only, with no attention mask |
| Preprocessing | Not downloaded: its values are pinned in code. From `preprocessor_config.json`: resize to exactly 224×224 with no crop, which squashes the aspect ratio (bicubic, `resample: 3`); scale by 1/255; mean `[0.5, 0.5, 0.5]`; std `[0.5, 0.5, 0.5]` |
| Embedding size | 768 (`text_config.hidden_size` in `config.json`; SigLIP base vision is also 768) |
| Download total | 213,373,093 bytes (the three downloaded files), shown as "213 MB", inside SPEC §5a's "150–350 MB" |
| URL form | `https://huggingface.co/Xenova/siglip-base-patch16-224/resolve/<revision>/<path>` |
| Licences | The original weights are **Apache-2.0** (`google/siglip-base-patch16-224`), and the model card has no clause restricting deployment. **The export repo `Xenova/siglip-base-patch16-224` carries no licence tag.** Its card only says it is the Google model with ONNX weights. This is a residual risk; see "Decisions". ONNX Runtime is MIT. `tokenizers` is Apache-2.0 |

The sizes and SHA-256 values above come from the Hugging Face API's LFS metadata at the pinned revision. The tokenizer was hashed after downloading it.

**Why the `_quantized` (int8) files:**
- ONNX Runtime's CPU execution provider runs dynamically quantised int8 well.
- Its fp16 coverage on CPU is partial.

Task 2's parity test, `quantized_close_to_reference`, is the check on this choice.

**Cost compared with CLIP ViT-B/32.** Patch 16 at 224 px gives 196 image tokens against 49, so encoding an image is roughly four times the work. Task 8 measures it.

**Still unverified:** whether `ort`'s prebuilt binaries link ONNX Runtime statically on all three operating systems. Task 2 Step 3 checks this on Windows.

## Global Constraints

- **Copy (SPEC §5a), verbatim:**
  - **First-run prompt:** "Turn on Find similar? It downloads a 150–350 MB image model and indexes your library in the background. Recommended for machines with 8 GB of RAM or more." The buttons are "Turn on now" and "Not now", and neither is pre-selected. The step also shows "Download: 213 MB · This computer: <N> GB RAM".
  - **Results label:** "Looks similar", always. Never "Related".
  - **English hint (decision 3):** the "Looks similar" group in the search dropdown carries the subline "Works best in English." whenever a typed query is shown.
- **Off means absent.** While `find_similar` is not `"on"`, the following are not rendered at all (not merely greyed out):
  - the "Looks similar" tab;
  - the dropdown section;
  - the drop target.

  Typed searches call only option A (`api.search`). Nothing else in the app depends on option B.
- **The model:**
  - It is never in the installer.
  - It is stored once per user, at `app_data_dir()/models/siglip-b16-224-q8/`, and shared across libraries.
  - It downloads only on an explicit "Turn on" (first run or Settings).
  - That download is the only network access in the app. It is an HTTPS GET of the pinned URLs with User-Agent `Horus/<version>`, and sends no identifying data.
- **Integrity:**
  - Each file downloads to `<name>.part`, resuming with `Range:`.
  - It is renamed into place only after its SHA-256 equals the pinned value.
  - A model directory is loaded only when every file matches (its `.ok` marker).
- **`embeddings.bin` lives in the library folder.** This adds one optional file to Plan 1's folder layout. It is a derived cache, so deleting it only means re-indexing.
- **Image input is `thumbs/1024/<hash>.jpg`.** Originals are never decoded (SPEC §9). A dropped external image is decoded once in memory and never copied into the library.
- **Indexing:**
  - runs at low priority in the background;
  - works in batches of `BATCH = 16`;
  - limits ONNX Runtime to `intra_threads = 2`;
  - sleeps `NAP_MS = 40` between batches;
  - can be paused;
  - never blocks a command for longer than one batch.
- **Scoring:**
  - L2-normalised 768-d embeddings, scored by dot product (cosine). SigLIP's sigmoid training loss doesn't change cosine ranking.
  - Its score **scale** differs by mode, though: text-to-image cosines run much lower than image-to-image ones. So the cut-off is set per model **and** per mode, in `ModelSpec`:
    - `sim_min_image`, provisionally `0.5`;
    - `sim_min_text`, provisionally `0.03`.

    Task 8 calibrates both on the demo set and records the values.
  - At most `SIM_K = 24` results are kept, highest first, excluding the query reference itself.
  - The UI shows "Looks similar" results **in rank order without a number**, because raw cosines across modes would mislead. The numbers stay in the API for tests.
  - `SIM_K`, `BATCH` and `NAP_MS` live in `similar/mod.rs`. The cut-offs live in `ModelSpec`.
- **No auto-tagging (SPEC §5a, §11).** No code path turns a similarity result into a tag or a suggested tag.
- **Execution provider:** the CPU only, in this plan.

## Review Focus

1. **The download is interrupted** (the network drops, the app quits, the laptop sleeps). The next "Turn on" or app start resumes from the `.part` file. A partly downloaded model is never loaded. Tested in Task 1.
2. **The server returns the wrong bytes**: an HTML error page, a truncated file, or a file changed upstream. The SHA-256 check rejects it and deletes the `.part`. The status shows "The download didn't match its checksum. Try again." The feature stays off. Tested in Task 1.
3. **The model can't start on this machine** (too little memory, an unsupported CPU, missing runtime libraries). The status shows "Find similar couldn't start: <reason>." `find_similar` returns to `"off"`, and the rest of the app works. Tested in Tasks 2 and 5.
4. **`embeddings.bin` is stale or damaged** (made by another model, truncated, holding deleted references, or copied from another library). It is pruned or rebuilt, never trusted blindly, and loading it never panics. Tested in Task 3.
5. **The library changes during indexing** (an import, a reference deleted, the library switched or closed, a pause). Nothing is written to the wrong library's `embeddings.bin`. New references are picked up on the next pass. Pause takes effect within one batch. Tested in Task 4.

  ```rust
  pub struct ModelFile { pub path: &'static str, pub size: u64, pub sha256: &'static str }
  pub struct ModelSpec { pub id: &'static str, pub repo: &'static str, pub revision: &'static str,
                         pub files: &'static [ModelFile], pub dim: usize,
                         pub text_len: usize, pub pad_id: i64, pub lowercase: bool,
                         pub sim_min_image: f32, pub sim_min_text: f32 }
  pub const SIGLIP_B16_Q8: ModelSpec;   // the table above: id "siglip-b16-224-q8", dim 768, text_len 64, pad_id 1, lowercase true
  impl ModelSpec { pub fn url(&self, f: &ModelFile) -> String; pub fn total_bytes(&self) -> u64; }

  pub enum DlEvent { Progress { done: u64, total: u64 }, Verifying, Done }
  pub enum DlError { Network(String), Http(u16), Checksum { path: String }, Io(String), Cancelled }
  pub fn download(spec: &ModelSpec, dir: &Path, client: &reqwest::blocking::Client,
                  cancel: &AtomicBool, on: &mut dyn FnMut(DlEvent)) -> Result<(), DlError>;
  ```
- **How `download` works**, file by file:
  - It skips a file that is already in place with the right size and SHA-256.
  - Otherwise it appends to `<path>.part` with `Range: bytes=<len>-`. If the server answers 200 instead of 206, it truncates the `.part` and starts again.
  - It hashes the finished `.part` and renames it into place only on a match. On a mismatch it deletes the `.part` and returns `Checksum`.
  - After every file passes, it writes the `.ok` marker last.
- **`app/notices/manual.md`** holds three entries, each with its URL, for Plan 6's generator:
  - **SigLIP:** "SigLIP base (google/siglip-base-patch16-224), Copyright Google LLC", the full Apache-2.0 licence text, and the upstream `NOTICE` reproduced if `google-research/big_vision` ships one. (None was found on 25 Nov 2026; this is unverified, so the implementer re-checks it.) Plus the ONNX export's origin, `Xenova/siglip-base-patch16-224` at the pinned revision.
  - **ONNX Runtime:** MIT.
  - **`tokenizers`:** Apache-2.0.

  ```rust
  //       u32 dim, u32 count, then count × ([u8; 32] blake3 image hash, dim × f32 LE). Written atomically (.tmp + rename).
  pub struct EmbStore { /* hash -> Vec<f32>, model_key, dim */ }
  impl EmbStore {
  ```

### Task 4: The background indexer

**Files:**
- Create: `app/src-tauri/src/similar/indexer.rs`.

**Interfaces:**
- Consumes `Embedder` (Task 2), `EmbStore` (Task 3), and `Library::thumb_path` (Plan 1 Task 2).
- Produces:
  ```rust
  pub struct IndexJob { pub root: PathBuf, pub items: Vec<(String /* hash */, PathBuf /* thumb1024 */)> }
  pub enum IdxEvent { Progress { done: usize, total: usize }, Paused, Finished { failed: Vec<(String, String)> } }
  pub struct Indexer { /* worker thread, Arc<AtomicBool> pause, Arc<AtomicBool> stop, generation: u64 */ }
  impl Indexer {
      pub fn start(job: IndexJob, embedder: Arc<Mutex<Box<dyn Embedder>>>, store: Arc<Mutex<EmbStore>>,
                   on: Box<dyn Fn(IdxEvent) + Send>) -> Indexer;   // skips hashes store.has(); BATCH, NAP_MS from mod.rs
      pub fn pause(&self, on: bool);
      pub fn stop(self);                                           // joins; at most one batch late
      pub fn generation(&self) -> u64;
  }
  ```
- **One generation per opened library.** `stop` is called before a different library is opened. Each `save` checks that the job's `root` still equals the state's open root before writing (Review Focus 5).
- **Saves:** the store is saved after every 8 batches and at the end, so a quit loses at most 8 batches of work.
- **Failures:** a thumbnail that fails to load or encode goes into `failed` with its reason, and indexing continues.
- **Shutdown:** the worker never holds the app-state lock. It holds only the store's own `Mutex`, for `put` and `save`.

  - `pause_within_one_batch`: after `pause(true)` mid-run, at most `BATCH` more calls happen, then `IdxEvent::Paused`. `pause(false)` finishes the job.
  - `stop_is_prompt_and_saves`: `stop` returns after at most one batch, and `embeddings.bin` holds every vector computed before the stop.
  - `no_write_after_root_changes`: when the guard says the root changed, the indexer exits without writing to the old root's file. Simulate it by flipping the guard closure (Review Focus 5).
  - `search_interleaves`: while a slow fake embedder indexes, a second thread's `text()` call through the same `Arc<Mutex<…>>` completes before the batch ends.
  - `failure_is_reported_and_skipped`: one failing item appears in `Finished.failed`, and the other 9 are stored.
  - `progress_monotonic`: `done` never decreases, and the last `Progress` equals `total`.

- **The encoder is shared** between the indexer and the search commands. Each side locks it per single image or query, never per batch, so a search waits at most one image while indexing runs.
- **Produces these commands.** All return `Result<_, String>`, and all JSON is camelCase.
  ```
  similar_status() -> SimilarStatus
  similar_enable() -> SimilarStatus        // sets find_similar "on"; downloads if needed, then loads, then indexes (all in the background)
  similar_disable() -> SimilarStatus       // sets "off"; stops indexing; frees the encoder; keeps files
  similar_remove_model() -> SimilarStatus  // disable + delete model dir and the open library's embeddings.bin
  similar_pause(paused: bool) -> SimilarStatus
  similar_by_ref(id: String) -> Vec<SimHit>
  similar_by_text(q: String) -> Vec<SimHit>
  similar_by_file(path: String) -> Vec<SimHit>   // import::decode_srgb in memory (size guard, EXIF, ICC, alpha on white); never imported
  ```
  ```rust
  pub enum Phase { Off, Downloading, Verifying, Loading, Indexing, Paused, Ready, Error }   // camelCase strings
  pub struct SimilarStatus { pub phase: Phase, pub download_done: u64, pub download_total: u64,
      pub indexed: usize, pub total: usize, pub disk_bytes: u64 /* model dir + embeddings.bin */,
      pub ram_bytes: u64 /* sysinfo total memory */, pub error: Option<String> }
  pub struct SimHit { pub id: String, pub score: f32 }
  ```
  Every phase change and every progress tick emits the Tauri event `similar://status` with a `SimilarStatus`, throttled to 4 per second.
- **The search commands:**
  - Each returns `Err("FindSimilarOff")` unless the phase is `Ready`, `Indexing` or `Paused`.
  - The results are for references already indexed.
  - Each command applies its own mode's cut-off: `sim_min_image` for `by_ref` and `by_file`, and `sim_min_text` for `by_text`.
  - `similar_by_ref` returns `Err("NotIndexedYet")` when the reference has no embedding.
  - Hits map from image hash to reference ids. Every reference that shares a hash is listed. `similar_by_ref` calls `top_k` with `exclude: None`, then removes only the query reference's own id after the mapping. Another reference with the same image therefore still appears.
- **At start-up and on library open, with `find_similar == "on"`:** the steps below run as Plan 6 Task 2's pipeline steps 1 ("stop the indexer") and 8 ("start the indexer"). Plan 5 does not order them itself (Cross-plan audit row 12).
  - if the model is installed, load it and index the missing references;
  - if it isn't, resume the download.
  - **Any load error** sets phase `Error`, with the message "Find similar couldn't start: <reason>.", and sets `find_similar` back to `"off"` (Review Focus 3).
  - **Indexing trigger (Cross-plan audit row 11):** this triggers on the result, not on the command. After any command whose `Change.references` include hashes that `EmbStore` lacks, and while the phase is `Ready`, `Indexing` or `Paused`, an index pass is queued for those hashes. The hook sits in Plan 2 Task 5's shared command recipe, so it covers `import_paths`, `import_bytes`, redo of an import, and Plan 6's orphan recovery. Before Plan 2 lands, it hooks Plan 1's `import_paths` only.
  - **`embeddings.bin` is deleted only by `similar_remove_model`.** Disable keeps it; a download in progress keeps it; opening a library never deletes it. A file made by another model is ignored and rebuilt by `EmbStore::load`.
