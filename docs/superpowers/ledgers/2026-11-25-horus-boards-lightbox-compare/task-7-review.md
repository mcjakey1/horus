### Issues

#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **The Shared column and the score go stale after any store change** (`compare/view.ts:183` and `:199`). `scorePair` runs once at mount, but every store event calls `render()`, which recomputes `onlyA`/`onlyB` from live tags against the old `scored.sharedTechniques`. You can hit this from inside Compare: press `L`, drag a region in the lightbox, and tag technique t3, which B already has. t3 then leaves `onlyB`, because A has it now, but never joins `shared`, so it shows in no column. The other way round, untagging (or Ctrl+Z, which works under Compare) a shared technique on A leaves it in Shared *and* puts it in `onlyB`. The score text is stale too. The score uses library-wide IDF (`correlate.rs:45-67`), so it also goes stale when *any* reference's tags change, not only A's or B's. **Fix:** on any store event with `references`, `removed` or `taxonomy` changes, call `scorePair(A, B)` again with a request counter so the latest reply wins, and keep the `closed` guard. Add a test: open Compare, `store.apply` a tag change on A with a second `scorePair` reply that differs, then assert that the second reply's Shared list and score text are rendered. Checking only that `scorePair` was called twice is not enough.
2. **Esc from a Compare opened in the Reference view resets that view and drops focus** (`firstrun.ts:52-55`, `reference/view.ts:86-118`). The default exit calls `showReference(A)`, which is `view.show(A)` with A already the focus. `show()` doesn't no-op on the same id. It clears `S.filter`, `S.pinned` and the arrival path, plays the `is-leaving` transition, and re-renders Ranked, Callouts and Links 180 ms later. Those three rewrite their pane's `innerHTML` (`renderCallouts` :242, `renderRanked` :327, `renderLinks` :349). So the artist's Ranked filter and pin are lost, and the Shift-clicked row that `close()` just refocused is replaced, which drops focus to `<body>`. That breaks "Esc closes it, returning focus" for the main entry. The unit tests mock `showReference`, so they can't see it. This is a plan gap, not an implementer deviation: the brief dictates this wiring (lines 34 and 51), so the controller should rule on the fix before the implementer departs from it. **Fix (pick one):** in `boot()`, call `view.show(id)` only when `id` differs from the Reference view's current focus (expose it, or let `show` skip the reset for the same id), or make `show(sameId)` a no-op for this caller. After an `x` swap, A is the original B, so navigating there is a real change. Decide whether that is the intended "return" and say so in a comment. Add a test through real `boot()` wiring, or a real `mountReference` plus `makeOpenCompare` with `showReference: view.show`: apply a filter, Shift-click, Esc, then expect the filter kept and focus on the row.
3. **The Tab-trap test can't fail** (`compare/view.test.ts:186-200`). jsdom never moves focus on Tab, so `dlg.contains(document.activeElement)` holds with or without `trap()`: focus simply stays on `first` and on `close`. The brief asks for "Tab stays inside it". **Fix:** assert `document.activeElement === close` after Shift+Tab on the first control, and `=== first` after Tab on `close`. Optionally also assert `defaultPrevented`.

#### Minor (Nice to Have)
1. **The plates overflow narrow windows.** `.cmp-tile` is `width: 420px; max-width: 100%`, but the plate and outline boxes are absolute px computed for 420. Between the 900 px breakpoint and about 1,150 px of window width, a side column is under 420 px. The tile background shrinks while the plate spills into the Shared column. Size the tile from the column (read its width, or use `min(420px, …)` and compute `tileBox` from the measured size), or raise the breakpoint.
2. **A store event while typing in the docked link editor steals focus.** `render()` refocuses `el` whenever focus is inside the dialog, including in `.cmp-dock`, which is never rewritten. Use `body.contains(document.activeElement)` for `inside`.
3. **Shared techniques vanish until the score arrives, and for good if `scorePair` rejects.** In both cases `shared` is `[]`, and `onlyA`/`onlyB` exclude the intersection anyway, so these techniques show nowhere. Consider falling back to the local intersection while `scored` is null. The score itself stays `scorePair`-only.
4. **Only the first region is outlined.** Hover uses `tags.find(...)`, so a technique tagged on two regions of one image outlines one of them.
5. **An unknown operation gets an empty label.** When `opOf` finds no operation it returns `""`, and the row renders " › Name" with an empty label. The neutral ink is correct.
6. **The `sides` comparator returns `NaN`** when both ids are missing from the taxonomy (`Infinity - Infinity`). It is harmless in V8, but `(a ?? MAX) - (b ?? MAX)` with a finite `MAX` is cleaner.
7. **The value view starts off.** The lightbox starts in the artist's current value view (`body.value`); Compare always starts off.
8. **Some keys and wiring are untested.** The `L` key in Compare is untested, though it shares the helper. The brief's Reference-view case says "Shift-click on a **Ranked** tile"; the test uses a callout thumb, which is the same handler. `beforePicker` is never exercised, because `openLb` already closes the margin picker, so the existing docking test passes through `closePicker()`, not `beforePicker`.
9. **`boot()`'s `view.destroy()` path doesn't close an open Compare.** This only matters for teardown in tests.
10. **The dialog has no accessible name.** The lightbox sets `aria-label` (`lightbox/view.ts:45`). Give Compare one, such as `Compare: A and B`, or point `aria-labelledby` at the titles.
11. **Compare's keys are bound on `el` only.** If focus falls to `<body>` (a notice dismissed over Compare, or the docked editor closing with its opener re-rendered), Esc, `v` and `x` stop working until focus moves back. The lightbox handles this with a capture keydown on `document` that re-sends the key (`lightbox/view.ts:301-307`).
